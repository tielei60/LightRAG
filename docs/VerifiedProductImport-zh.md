# 可核验的产品导入与原生读回

本轮以 `000a01c9f6a5a53f5c9861a6486e392d3a04c4de` 为基线，优先解决导入保真、适用范围、必要条件和来源对应。保留原生 LightRAG 的文档、图、向量及查询流程，不建设另一套产品主数据或保险规则执行系统，不修改 WebUI，也不把统一 HTTP 接口作为前置任务。

验证必须分别回答三件事：原文和核准结果是否实际存入；固定原生查询是否取到完整依据；最终模型是否正确表达。前两项通过不能代替第三项。测试集通过率不是每条回答的可靠概率。

## 冻结的失败基线

已有本机试验的源码基线为上述提交，同一产品的条款、说明书和投保核保规则三份资料。六个问题分别运行原生提示及完整原文提示，两臂共十二份答案。独立审读结果为原生一项通过、三项部分通过、两项失败；完整原文零项通过、三项部分通过、三项失败。部分通过仍有实用价值，不等于全部答错；这组单次小样本不能估计稳定错误率。

该试验使用 `qwen3.8-flash`，temperature 为 0，max_tokens 为 2048，非流式且关闭 thinking；向量模型为 `qwen3.7-text-embedding-flash`、1024维。私有端点、请求、原答及逐处定位留在用户本机，不随源码发布。后续导入实验必须另建候选，不改写或重新生成这些基线记录。

已经确认两种不同问题：

- 部分抽取关系只保留标题或首句，遗漏后续条件；部分图关系有两段依据，但最终原文区域只带入一段。这是导入或证据传递问题。
- 同次实际提示已经包含完整原文，答案仍漏掉重大过失的附加条件、改换等待期事件或把通知例外提升为充分赔付条件。这是已观察到的生成错误，不能声称补齐导入便已解决。

本轮没有新增真实模型调用。公开合成回归仅复现 AND/OR、局部范围、后置定义、同文多出处和完整例外等一般结构，不包含私有答案或产品专用推理分支。

## 本轮实现边界

使用已审核原文区间准备完整检索单元，再把核准抽取选择封存，原生写入时回放同一份结果，而不是重新随机抽取。任何不匹配停止该候选，不退回默认模型。

准备记录复用调用方的产品和文档身份。文档修订标识是技术绑定的一部分，不根据文件日期或哈希虚构业务产品版本。原文身份按来源、解析版本和位置保留，同样的文字出现在两个来源仍是两个出处。

范围使用明确组合，区分特定范围、已确认通用、不适用和未知。未知不能默认为通用。必要依赖可以指向同一文件后面的定义或例外，但必须有审核依据并完整进入片段。上下文副本不是新增事实，不把重复引用次数当作更多独立证据。

原生关系 weight 仍可能随贡献 chunk 数增加，本轮没有改变其算法。它不是独立原件数量、业务置信度或多方佐证强度；独立来源与上下文副本的区分以位置账本为准。

首轮只支持 PDF、Markdown、TXT 的既有文字解析及已审核边界，不声称自动理解所有表格、脚注或计划关系。跨文件组合、DOC/DOCX、OCR、线上补证、生产增量更新及自动语义审批不在本轮支持范围。需要这些能力的资料必须明确标记未支持，不能悄悄省略。

哈希、ID和原文相等检查只证明绑定与完整性，不证明业务语义正确。核准记录需要独立可信的审核输入；不能从待导入对象自行计算一个哈希，就把它称为审核通过。

## 工具与本地操作

`product.import_units` 负责来源检查、审核区间、范围组合、必要依赖和完整片段。`product.import_proposals` 生成未核准的抽取请求，并可由显式授权的调用方收集候选。`product.approved_import` 编译核准候选、回放原生抽取、写入及新进程读回。这些工具不接管现有 `/query` 或 WebUI。

先按 [本地环境准备](LocalValidation.md) 安装锁定依赖。下面是**虚构资料、离线向量**演示，不能用于评估真实检索质量，不需要密钥。tokenizer 编码缓存缺失时，缓存准备命令会下载公开编码文件，不是模型调用。

```sh
export PYTHON_DOTENV_DISABLED=1
export TIKTOKEN_CACHE_DIR="$PWD/.cache/tiktoken"
.venv/bin/lightrag-download-cache --tiktoken --cache-dir "$TIKTOKEN_CACHE_DIR"
.venv/bin/python -m product.approved_import demo data/verified-import/demo-001
```

目标必须全新。演示生成两个文字相同但来源不同的虚构文件、固定合成核准记录以及独立候选；不能用此演示核准任意真实文件。查看输出目录中的 `receipt.json`、`sealed.json`、`events.jsonl`、`persisted-readback.json` 和 `readback-report.json`。终端给出的 seal SHA 可用于再次检查：

```sh
.venv/bin/python -m product.approved_import readback \
  data/verified-import/demo-001/sealed.json \
  data/verified-import/demo-001 --pin <演示输出的seal摘要>
```

原生 context/prompt 演示使用确定性假向量、固定关键词和宽预算，报告保存实际配置及命中的证据编号。它只测试原生查询路径连通，**不是生产召回率或答案准确性证明**。真实资料的固定原生查询验收仍需新的调用授权和独立评测。

真实资料准备采用下列步骤，检查文件不能自动变成已审核清单：

```sh
.venv/bin/python -m product.import_units inspect 原件.pdf 原件检查.json \
  --source-id 已有文档标识 --document-version 已确认修订标识
.venv/bin/python -m product.import_units prepare 审核后的清单.json 准备结果.json \
  --root 原件目录
.venv/bin/python -m product.import_proposals 准备结果.json 待抽取请求.json \
  --model 实际抽取模型 --input-token-limit 32768 \
  --context-token-limit 65536 --max-output-tokens 8192
```

最后一条命令只写请求，**不会调用模型**。token预算必须按实际模型调整；这里是接口示例，不是提供方默认值。请求完整序列化后按配置的tokenizer检查输入及输出预留，提供方chat封装差异仍由实际调用适配核对。

需要自动收集模型候选时，Python API `collect_proposals` 要求调用方提供模型函数、明确调用次数上限及持久记录函数。每次调用前先记录实际请求，随后保存同次实际响应、完成状态、用量和耗时；不自动重试技术不明结果或语义失败，也不自动核准。凭据、HTTP头和未知元数据不属于记录合同。本轮只用假回调测试，未消费真实调用额度。

审核后使用 `build_review_packet`、`seal_review` 和 `import_candidate`。核准摘要由可信调用方独立保留，审核对象是完整片段、范围、抽取选择和运行配置。审核者身份真实性由调用方负责，并未新增一套用户或审批系统。真实embedding通过Python API显式注入与指纹一致的 `EmbeddingFunc`；现有CLI的import/readback只支持明确标记的离线演示，不会静默读取本地密钥或调用默认提供方。

初始核准合同面向小型完整规则单元：每个图对象携带该单元及其全部已登记依赖，避免在选择阶段漏掉条件。它可能重复描述，不能称为任意长文的最优图谱。可明确审核为 `text_only`，保留原文片段及向量而不造图对象；未声明的空模型输出仍不算完成。后续需要减少重复时，应先测图/原文预算和完整证据覆盖，不能直接删掉限制句。

## 原生约束

原生抽取会规范化图描述的部分全角符号与空白。保留原生 chunk 和来源账本中的原文；图描述按实际已知规范化检查，并保留清楚的原文位置标记。不得将图描述声称为原件的逐字节副本。

原生图来源上限、描述合并及上下文预算都可能造成信息损失。候选导入需要验证实际参与的来源，而不是从整个批次账本补出未绑定的证据。落盘读回应检查片段、图对象、三类向量、来源跟踪及文档恢复锚点，不能只检查 processed 状态。

运行仅面向全新、隔离的本地候选工作区。不能与另一个写入进程并行修改同一库，不能删除旧回执以强制重放；不明结果保留并先核对。失败候选不代替已经使用的基线。

## 验收与下一步

先做不调用提供方的合成原生流水线验证，确认准备、核准、写入、关闭实例、重新读取的结构不变量。随后获得新的真实调用授权后，才用真实资料、相同模型与查询参数检查检索及答案。

真实验收保持问题和金标分离，金标只在输出完成后评分。至少区分索引缺失、关键证据未进实际提示、证据齐全仍答错、错误引用、可答题拒答及超预算。计划串用、金额或比例基数错误、关键免责遗漏单列，不能被平均分掩盖。

先验收一款产品的完整资料，再加入相近产品及版本的同库干扰。保留未参与调整的新题，核心问题重复运行，冷缓存与热缓存分开，报告实际样本数、调用数、token和耗时。不能通过提高每题预算、换模型或手工指定正确证据，把收益全部归因于导入。

若证据和索引正确，但原生查询仍持续遗漏必要内容，记录召回或预算未通过；若完整证据已进入实际提示但回答错误，记录生成未通过。不以全量重导、增加节点或全拒答替代问题定位。
