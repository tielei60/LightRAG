# 本地证据扩展的验证与限制

本记录对应 `codex/jkyh-explicit-source-links` 外置实验代码。未修改 LightRAG 核心、WebUI、产品主数据或旧知识库。实验资料、完整提示、模型输出、私有配置及运行日志只保留在本机忽略目录，不随代码提交。

## 已验证的结构改进

`product/prepare_batch.py` 在原件和解析全文摘要一致时生成完整条款分块；示例清单在 `product/clause_context/`。示例包含产品资料的定位边界，不包含产品专用推理分支。

`product/source_links.py` 只编译经核对的显式“见释义”引用及原文结构归属，保留支持范围；不按孤立节点数量造边。一次隔离实验从146节点、116边、36孤点变为146节点、156边、0孤点。40条新关系逐条核对来源，原有节点及边属性未改写。图连通不代表语义完整或回答正确。

关系写入的完整文档恢复锚点、删除及重导生命周期尚未验收。因此该图仍是查询实验副本，不能作为生产库迁移方案。

## 真实问答仍有失败

`products_scoped.md` 是可选实验指导，不是已验收修复。已有单次对照中，完整相关原文已在当次生成提示内，模型仍出现定义范围扩大为合同拒赔、替代条件“或者”改成“且”、通知例外扩大为充分赔付条件，以及正确事实绑定错误文件引用等问题。不要推广该提示为可靠业务保护。

另有证据传递问题：图关系保存了两个原文片段，但最终提示的原文区域只选入一个；缺少的释义仅以图描述到达模型。证据图可追溯与最终原文证据完整是两个不同指标。通用提示要求综合图信息，而产品提示将图限定为定位用途，也需要分离证据权限后再验证。

这些观察来自保存的同次请求、输出及原文，不是重新检索出的替代上下文。有限且单次的试验能确认失败存在，不能估计稳定错误率，也不能把组合改动归因于单一变量。

## 本轮安全边界

新增外置答案证据模块的目标是确定性地发布完整原文摘录，并将所有自由改写和推断保留为未审读候选。引用编号有效、哈希正确、输出未截断，只能证明机械合同成立，不能证明语义蕴涵。

详细接口、离线入口及适用边界见 [答案证据门禁](../product/answer_evidence.md)。模块不自动接管原生 `/query`、`/query/stream` 或 WebUI。现有原生服务仍可能输出未审读答案，不能因新增离线模块而称其已受到保护。

原文摘录只保证本次选中的完整证据和已登记依赖被保留，不保证检索召回全部适用条文，也不作承保或理赔判断。后续若接入流式界面，必须先验证再发布业务内容，不能先输出模型答案、事后再撤回。

真实失败回放和合成反例的结果应分别报告。将自由解释全部降级为摘录是覆盖能力的取舍，不是回答准确率提升的证明。新增模型评估应冻结问题与证据包，分别报告语义错误、错引、缺证、拒答/摘录比例、有用覆盖及成本；不使用模型自报置信度作为放行依据。

## 本轮离线结果

- 相关子集242项通过：新答案门禁114项、条款准备/引用扩展/证据抽取相关62项、既有外置证据工具66项。不是全仓库或前端验收。
- 全程禁网并禁用 dotenv 与项目 conftest；需要的 tokenizer 使用已存在的本机缓存，异步测试插件显式载入。Ruff与新模块格式检查通过。
- 独立代码审读和进程内突变覆盖了原文相等检查、当前证据包比对、依赖摘录与候选正文泄漏；故意去掉保护后，相关测试会失败。
- 三个旧回答的完整实际检索投影均因有限目录覆盖不足而阻断，公开摘录为零。
- 三个另行标记的人工选文案例只发布完整原文；六条保留原样的旧错误解释均待语义审读，未发布。三个完整原文控制样例通过精确核验。
- 没有新增模型调用、真实问答生成或线上效果测量。人工选文正路径不能描述成自动检索改进，全拒答也不能描述成答对。

下一步优先验证导入后的实用问答，而非扩展统一服务接口。建议冻结原始失败回归与新题，使用同次检索分别构造原生提示及完整原文证据包，保留每次实际请求、原答、引用和用量。自由答案的语义质量须独立对照原文评分；摘录/拒答是单独结果类别，不能代替正确且有用的回答。统一导入、查询和链路接口的接入留到后续，不将其作为本次已完成事项。
